## Historical findings that are safe to retain

The strongest historical native result is a bounded, completed-call CPU/WGPU crossover on one Windows RTX 4050 host, 100k by 384 AG News embeddings, batch one, and five runs per cell. CPU wins at E=2,000 (0.5198 ms P95 versus 0.6340 ms compact-row WGPU); compact-row WGPU wins at E=3,000 (0.8144 ms versus 0.9563 ms). The measured bracket is therefore `(2k, 3k)` for that implementation, device, dimension, batch, predicate, and timing boundary. It is a bracket, not a fitted threshold. All six crossover cells have recall@10 of 1.0 against the retained FP64 oracle.

The same sweep makes static routing regret concrete. Applying the 4,096-row rule counterfactually misroutes E=3,000 and 4,000, with 17.4239% and 23.9173% relative P95 regret. This is a cell-level post-hoc counterfactual, with no held-out policy evaluation or confidence interval. It should support a negative conclusion about universal thresholds, not a claim that an adaptive router has been validated.

The eligibility-materialization ablation is a separate RTX 4090/Vulkan cohort. It compares legacy two-pass, one-pass, and generation-keyed cached preparation at E=1k, 4k, 6k, and 100k with identical 100k by 384 data and five complete runs per mode/cell. It supports the preparation-cost mechanism and exact semantic equivalence; its sequential execution and one host limit generalization. The archive is `qenlo-phase1-eligibility-2026-09-04.tar.gz` (SHA-256 `26e0ccc057c59c0fb4687f8d85a923e88b7bb25257e4e551e22cffe13c1b821f`).

The Windows endpoint and the historical Linux replay are useful context, with incompatible boundaries kept visible. Windows all-row P95 is 16.6567 ms CPU, 3.2404 ms WGPU predicate, 4.2428 ms compact rows, and 4.4591 ms mask. The Linux replay uses three repetitions and external API/storage boundaries; it reports Qenlo CPU 12.901 ms, FAISS Flat 10.217 ms, USearch 5.093 ms, FAISS HNSW 1.494 ms, Chroma 3.777 ms, Milvus 76.229 ms, and LanceDB Flat 242.256 ms. These rows answer different questions and must not be pooled.

## Platform-specific evidence

The Android and Intel Arc records are valuable portability observations and are not substitutes for one another. Android is author-supplied aggregate data from Android 16/API 36, MediaTek MT6897, Mali-G615 MC6, and Vulkan. All 21 cells report recall@10=1.0 and no fallback. Its 100k by 384 soak reports CPU P95 27.019 ms, WGPU exact 17.678 ms, and batch-eight WGPU 11.131 ms. No raw calls are retained; `thermal_state="0"` and null power source are not interpreted.

Intel Arc `reports.json` is internally consistent across three supplied reports: two `quick` runs with seven cells and 16 samples/cell, and one `soak` run with seven cells and 512 samples/cell. The 100k by 384 soak reports exact WGPU P95 4,444 microseconds, CPU 16,486 microseconds, IVF-Flat 2,704 microseconds, and IVF-SQ8 22,797 microseconds. Every cell reports recall@10=1.0 and no fallback. One report was externally described as “full” but embeds `suite="quick"`; the JSON value is authoritative and remains labeled quick. This is a single-device aggregate submission, not an independent raw-call replication.

Neither device-lab cohort establishes iOS-device support, and neither justifies inference from cloud NVIDIA results. No physical iOS run was found in the retained evidence.

## A6000 and competitor evidence

The synthetic A6000 table is a separate PyTorch/CUDA research prototype, not shipped Qenlo Rust/WGPU. It shows a reversal relative to FAISS GPU Flat: the prototype loses at E=1k and 10k and wins at E=100k and 1M. Both implementations agree on unordered top-10 lists, but there is no independent FP64 oracle and eligibility is pre-materialized outside timing. This is useful negative/context evidence and cannot be called a Qenlo product result.

The real strict TopK A6000 table is stronger on correctness but still negative on the proposed advantage. At the retained E=10,026 strict cell, FAISS GPU Flat is 0.132222 ms P95, NumPy CPU is 0.197311 ms, and the CUDA prototype is 0.170722 ms; all three valid rows have FP64-oracle recall 1.0. cuVS recall 0.9 is disqualified and retained as a failure. The prototype is slower than FAISS and does not meet the preregistered 2x CPU gate. The earlier provider-compatible approximately-1% report uses `<=` semantics and a prefiltered matrix, so it is not the strict gate.

Chroma, USearch, FAISS HNSW, Milvus, and LanceDB are retained with recall beside latency. Chroma and USearch rows are ANN; FAISS Flat and LanceDB Flat are exhaustive but use external API boundaries. The evidence supports scoped paired observations only. It does not support “fastest database” or a universal exact-versus-ANN ranking.

Any final caption should state the implementation, hardware, dimension, timing boundary, and correctness condition for each panel.

## Missing or excluded historical claims

`research/data/processed/evidence_completeness.csv` marks dimension effect, matched corpus size, metadata correlation, and calibrated routing regret as unmeasured or unavailable. No retained figure can turn these into measured claims. The historical files also preserve:

- the Vulkan failure on the RunPod RTX 3070 replay, with no GPU timing and no mislabeled CPU fallback;
- cuVS recall failure and runtime-library failures in the A6000 attempts;
- Qdrant exclusion because its local mode changes to exact brute force above 20,000 points;
- aggregate-only Android evidence;
- no physical iOS evidence;
- no 1M by 768 shipped Qenlo WGPU result;
- no ANN recall-latency frontier, concurrency/QPS matrix, energy measurement, or multi-device matched study.

These are documented exclusions or limitations, not missing green rows. They should remain visible in the definitive paper's threats-to-validity and evidence ledger.

## Reconciliation checks

The reduced historical directory generated by `paper/scripts/reduce_final_evidence.py` contains nine CSVs: `a6000_exact_summary`, `a6000_strict_summary`, `android_device_lab`, `eligibility_ablation_summary`, `evidence_inventory`, `linux_library_summary`, `native_crossover_summary`, `static_router_regret`, and `windows_summary`, plus the JSON form of the A6000 synthetic table. Their parsed CSV rows match the retained processed originals; this is semantic row equality, not a byte-for-byte file comparison. The raw aggregation verifier [`verify_historical_raw.py`](verify_historical_raw.py) recomputes native lower-middle run P95 values from `runs.csv`, reads all eligibility-ablation run files directly from the immutable tar archive, and recomputes A6000 P50/P95/P99 from retained per-call samples; it passes all checks. The independently checked counts are 225,000 Windows endpoint observations, 300,000 Windows crossover observations, 300,000 eligibility-ablation observations, 10,500 Linux-library observations, 4,000 synthetic A6000 observations, 20,000 real strict A6000 observations, and 4,144 Android aggregate observations. These are artifact-volume counts, not independent replications.

The historical audit is complete when the definitive manuscript preserves these cohort boundaries, cites the ledger entries for each headline claim, and leaves untested platform, dimension, router, and ANN claims explicitly open.
