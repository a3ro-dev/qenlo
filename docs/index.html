Qenlo documentation

Embedded vector search that explains its work.

Qenlo is a Rust vector database for native applications. It keeps canonical vectors and metadata local, applies filters before ranking, and returns an execution report with every search.

Current truth: the exact CPU path, durable storage, portable .qn files, multi-language SDK boundary, and Windows GPU paths are implemented. The predeclared 1M × 768 research gate remains untested.

Start

Quickstart

The API shape stays consistent across every binding: create, add, search, inspect, close.

let db = Collection::new(CollectionConfig::cpu_exact(3)).await?;
db.add(1, 7, 10, &[1.0, 0.0, 0.0])?;
let response = db.search(&[1.0, 0.0, 0.0], &Filter {
    user_id: Some(7), ..Filter::ALL
}, 10).await?;
assert_eq!(response.results[0].id, 1);
from qenlo import Collection, Filter, Record

with Collection.memory(3) as db:
    db.add(Record(1, 7, 10, (1.0, 0.0, 0.0)))
    response = db.search((1.0, 0.0, 0.0), Filter(user_id=7))
    assert response.results[0].id == 1
import { Collection } from "@qenlo/qenlo";

using db = Collection.memory(3);
db.add({ id: 1n, userId: 7n, timestamp: 10n, vector: [1, 0, 0] });
const response = db.search([1, 0, 0], { userId: 7n });
db, err := qenlo.New(3)
if err != nil { log.Fatal(err) }
defer db.Close()
err = db.Add(qenlo.Record{ID: 1, UserID: 7, Timestamp: 10,
    Vector: []float32{1, 0, 0}})
QenloCollection.memory(3).use { db ->
    db.add(Record(1u, 7u, 10, floatArrayOf(1f, 0f, 0f)))
    val response = db.search(floatArrayOf(1f, 0f, 0f), Filter(userId = 7u))
}
let db = try QenloCollection(memoryDimension: 3)
defer { try? db.close() }
try db.add(.init(id: 1, userID: 7, timestamp: 10, vector: [1, 0, 0]))
let response = try db.search([1, 0, 0], filter: .init(userID: 7))

Ordering and filter rules

  • Cosine distance is ascending. Equal distances are ordered by public ID.
  • user_id is optional equality. Timestamp lower bounds are inclusive; upper bounds are exclusive.
  • Public IDs are unique and never reusable, including after deletion.

Concepts

Core concepts

Canonical first

Vectors, metadata, tombstones, and generation are canonical. CPU and GPU indexes are replaceable views. A stale derived index is rebuilt or rejected; it never becomes the source of truth.

One committed generation

A search observes one complete generation. Batch mutations validate atomically before publication, so readers do not see partial batches.

Backend selection is visible

Automatic may use exact CPU search or a GPU path. The execution report names the requested backend, actual backend, algorithm, routing reason, fallback reason, bytes moved, and measured timing.

SDK

Python

python -m pip install qenlo

Use Collection.memory, create, open, or import_qn. Context manager exit closes the native handle. IDs are validated as unsigned 64-bit values and timestamps as signed 64-bit values.

db.export_qn("vectors.qn")
portable = Collection.import_qn("vectors.qn", dimension=384)

SDK

TypeScript

npm install @qenlo/qenlo

IDs and timestamps use bigint, preserving the full native 64-bit range. The package is ESM and supports explicit resource management through using.

using db = Collection.importQn("vectors.qn", 384);
db.exportQn("copy.qn");

SDK

Go

go get github.com/a3ro-dev/qenlo/sdk/go

The binding uses cgo. Keep the matching native library beside the package or in the platform loader path. Close is idempotent; use errors.As with *qenlo.Error for native failures.

SDK

Kotlin

implementation("dev.qenlo:qenlo:0.1.0")

The API uses Kotlin unsigned types for IDs and AutoCloseable for deterministic cleanup. JNA loads qenlo_ffi from QENLO_LIBRARY_PATH or the system library path.

SDK

macOS and iOS

The Swift API uses UInt64, Int64, typed value objects, and explicit close semantics. Source checkouts link a compiled libqenlo_ffi; release packages require an XCFramework containing the matching Apple slices.

let db = try QenloCollection(importQN: fileURL, dimension: 384)
try db.exportQN(to: destinationURL)

Operate

Storage and portable files

Durable collection directory

Use create and open for writable state across restarts. Commits append checksummed WAL transactions. Flush and close compact to a canonical snapshot.

Portable .qn

A .qn file is a create-only, checksummed interchange snapshot. It retains tombstones and generation but excludes derived indexes, telemetry, locks, and embedding models.

  1. Write a sibling .qn.pending file with exclusive creation.
  2. Flush and sync the complete payload.
  3. Publish without replacing an existing target.
  4. Sync the parent directory where the platform supports it.

Execution reports

Every search response includes results plus an execution report. Optional measurements are explicitly unavailable when the backend cannot provide them.

Research

Benchmarks and gate

Predeclared investment gate1M × 768, 1% eligible, batch 1, k = 10Untested

Existing 100k × 384 measurements are evidence for their exact devices and cells. They do not close the larger gate and are never generalized into a universal performance claim.

Comparison contract

  • Independent float64 exact oracle.
  • Every attempt retained, including failures and fallbacks.
  • P95 uses nearest-rank calculation with declared warmups and repetitions.
  • Dataset selection, checksums, hardware, drivers, and build inputs recorded.

Research

Device lab

The lab turns trusted tester hardware into a reproducible station. Reports name the real adapter and API, keep failures, and remain local until the tester explicitly submits them.

Latest retained device: an Intel Arc Vulkan soak run passed all seven cells at Recall@10 = 1.0. Exact GPU P95 was 4,444 µs versus exact CPU P95 16,486 µs. This is device evidence, not the 1M × 768 gate.
