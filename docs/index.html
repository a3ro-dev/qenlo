Qenlo documentation

Embedded vector search that explains its work.

Qenlo is a Rust vector database for native applications. It keeps canonical vectors and metadata local, applies filters before ranking, and returns an execution report with every search.

Current truth: the exact CPU path, durable storage, portable .qn files, multi-language SDK boundary, and Windows GPU paths are implemented. A strict 1M × 768 CUDA prototype gate was run and did not beat FAISS; the equivalent shipped Rust/WGSL gate remains open.

Ordering and filter rules

  • Cosine distance is ascending. Equal distances are ordered by public ID.
  • user_id is optional equality. Timestamp lower bounds are inclusive; upper bounds are exclusive.
  • Public IDs are unique and never reusable, including after deletion.

Concepts

Core concepts

Canonical first

Vectors, metadata, tombstones, and generation are canonical. CPU and GPU indexes are replaceable views. A stale derived index is rebuilt or rejected; it never becomes the source of truth.

One committed generation

A search observes one complete generation. Batch mutations validate atomically before publication, so readers do not see partial batches.

Backend selection is visible

Automatic may use exact CPU search or a GPU path. The execution report names the requested backend, actual backend, algorithm, routing reason, fallback reason, bytes moved, and measured timing.

Quickstart: In-Memory and Durable Collections

use qenlo::{Collection, CollectionConfig, Filter, NewRecord, TimestampRange};

#[tokio::main]
async fn main() -> Result<(), qenlo::Error> {
    // 1. In-memory collection
    let mem_db = Collection::new(CollectionConfig::cpu_exact(3)).await?;
    mem_db.add(1, 42, 100, &[1.0, 0.0, 0.0])?;
    mem_db.add(2, 42, 200, &[0.0, 1.0, 0.0])?;

    // 2. Search with compound user/time filter
    let filter = Filter::new(Some(42), TimestampRange::new(Some(50), Some(150)));
    let response = mem_db.search(&[1.0, 0.0, 0.0], &filter, 5).await?;
    println!("Hit ID: {}, Distance: {}", response.results[0].id, response.results[0].distance);

    // 3. Durable collection on disk
    let config = CollectionConfig::cpu_exact(128);
    let disk_db = Collection::create("./my_store.qenlo", config.clone()).await?;
    disk_db.add_batch(&[
        NewRecord { id: 10, user_id: 7, timestamp: 1000, vector: vec![0.1; 128] },
        NewRecord { id: 11, user_id: 7, timestamp: 1001, vector: vec![0.2; 128] },
    ])?;
    disk_db.flush()?;
    disk_db.close()?;

    // 4. Reopen across application restarts
    let reopened = Collection::open("./my_store.qenlo", config).await?;
    let stats = reopened.stats();
    println!("Reopened collection with {} live rows", stats.live_rows);
    reopened.close()?;
    Ok(())
}

Portable .qn File Roundtrip

// Export collection to a single immutable .qn file

// Import into a fresh in-memory collection

Concurrency and Thread Safety

Wrap Collection in an Arc<Collection> to share across tasks. Search operations share a read lock; mutations and rebuilds take a write lock. Close is explicit and idempotent.

Quickstart

from qenlo import Collection, Filter, Record

# In-memory collection with context manager lifecycle
with Collection.memory(dimension=3) as db:
    db.add(Record(id=1, user_id=42, timestamp=100, vector=(1.0, 0.0, 0.0)))
    db.add(Record(id=2, user_id=42, timestamp=200, vector=(0.0, 1.0, 0.0)))

    # Search with combined metadata filter
    response = db.search(
        query=(1.0, 0.0, 0.0),

    # Inspect execution telemetry
    report = response.report
    print(f"Backend: {report.actual_backend}, Total: {report.total_duration_ns}ns")

package main

    if err != nil {
        log.Fatal(err)
    }

    for _, hit := range response.Results {
        fmt.Printf("Hit ID: %d, Distance: %.4f\n", hit.ID, hit.Distance)
    }
    fmt.Printf("Backend: %s in %dns\n", response.Report.ActualBackend, response.Report.TotalDurationNS)
}

Operate

Storage and Portable Files

Crash-safe write-ahead logging (WAL), atomic compaction, and single-file portable interchange.

Durable Collection Directory

A durable Qenlo directory maintains canonical vectors and metadata with transactional crash safety:

ArtifactFormatPurpose
manifest.qmfCRC32-checksummed JSONTracks active generation, snapshot pointer, and WAL sequence
wal-*.qwalAppend-only CRC32 blocksSynchronous write-ahead log records for durable transactions
snapshot-*.qdbMmap-optimized binaryCompacted canonical store (vectors, IDs, timestamps, tombstones)
HEADAtomic 64-bit watermarkCommitted generation barrier preventing rollback on restart

Portable .qn Format v1

A .qn file is a standalone, checksummed, immutable interchange snapshot for vector portability across machines and architectures without running a server:

  1. Magic & Version: 4-byte ASCII QNLO followed by u32 format version 1.
  2. Header: Vector dimension, row count, live count, canonical generation, and metadata bounds.
  3. Payload: Normalized FP32 vectors, uint64 IDs, uint64 user IDs, int64 timestamps, and tombstone bitset.
  4. Trailing CRC32: Final 4-byte checksum validating full file integrity from byte 0.

Atomic Non-Overwriting Publication Protocol

  1. Write payload to a sibling .qn.pending file with exclusive file creation (O_EXCL / CREATE_NEW).
  2. Flush and fsync the complete payload to durable media.
  3. Atomically rename/publish without overwriting an existing target.
  4. Fsync the parent directory on Unix systems.

Recovery Policy

Self-healing is bounded, transparent, and fail-closed. Canonical data is never silently invented or discarded.

Self-Healing Guarantees and Limits

Fault / StateAutomatic ActionSafety Boundary
Valid interrupted .qn.pending Validate checksum, publish target, record recovery in stats Target file must be absent
Stale or missing derived index Discard marker and trigger synchronous rebuild Canonical vectors and tombstones remain authoritative
GPU device lost in Automatic mode Route query to exact CPU path and disclose fallback reason Required(GPU) mode returns an explicit error
Checksum failure or generation ambiguity Preserve damaged files, fail closed with error No guessed repair; operator inspection required

Anonymous Telemetry Policy

Mandatory Anonymous Telemetry: All Qenlo SDK installations securely transmit anonymous platform, architecture, SDK version, and search latency metrics to https://api.gobitsnbytes.org/qenlo/telemetry. This telemetry is strictly anonymous, privacy-preserving, and mandatory across all SDK distributions (no opt-out) to monitor reliability and optimize hardware search routing.
