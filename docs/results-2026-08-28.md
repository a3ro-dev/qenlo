# measured results: 2026-08-28

This is the reproducible result record for the native Windows benchmark run. It
is deliberately narrower than a product claim: one laptop, one real embedding
source, five measured repetitions per cell, and the exact workload definitions in
the [benchmark protocol](benchmark-protocol.md).

## machine and data

- Windows 11, Intel Core i5-13420H, 12 logical processors, 16.87 GiB RAM.
- NVIDIA GeForce RTX 4050 Laptop GPU, 6,141 MiB, driver 616.56, alongside Intel
  UHD Graphics as the integrated adapter. The GPU cells requested the
  high-performance adapter and record `gpu_adapter`, `gpu_api=Dx12`, and
  `gpu_device_type=DiscreteGpu`; they are actual NVIDIA device runs, not CPU
  fallbacks.
- Rust 1.98.0, release build with `CC=clang-cl`, `CXX=clang-cl`,
  `CARGO_INCREMENTAL=0`, and features `usearch,gpu-wgpu`.
- 100,000 rows × 384 dimensions from the DTU AG News
  `all-MiniLM-L12-v2` HDF5 source. The source checksum, license, author, and
  extraction details are in [the dataset record](../benchmarks/2026-08-28/real/dataset/ag-news-384.json).

The corpus, tuning queries, and evaluation queries are disjoint. Every cell used
the same metadata, compound user-and-time filter, query order, k=10, 200 warmups,
five repetitions, and a 0.95 recall target. P95 is the lower-middle value of the
five run P95 samples. Exact backends use an independent f64 oracle; one exact
result at a floating point boundary may choose a different tied ID, which is
accepted only within the documented 1e-5 boundary tolerance. Filter violations
were zero in every completed cell.

## all eligible rows

This is the 100,000-row cell with all rows eligible. Latencies are P95 per batch
in milliseconds; recall is evaluation recall@10.

| backend | median P95 | tuning recall | evaluation recall | result |
| --- | ---: | ---: | ---: | --- |
| Qenlo exact CPU | 16.6567 ms | 1.00000 | 0.99998 | passed |
| Qenlo GPU predicate | 3.2404 ms | 1.00000 | 0.99998 | passed |
| Qenlo GPU rows | 4.2428 ms | 1.00000 | 0.99998 | passed |
| Qenlo GPU mask | 4.4591 ms | 1.00000 | 0.99998 | passed |
| Qenlo USearch (ANN, ef=128) | 3.6245 ms | 0.99320 | 0.99224 | passed |
| Chroma PersistentClient (ANN, ef=128) | 1.1303 ms | 0.99450 | 0.99414 | passed |

The Qenlo GPU predicate cell is 5.14× lower than the Qenlo exact CPU cell for
this workload (seeded whole-run bootstrap interval 3.55×–6.77×). USearch is
1.12× lower than GPU predicate, with a coarse interval of 0.77×–1.54×. Chroma
is lower still, but that comparison crosses an API boundary: it includes the
Python `PersistentClient` call, native bindings, serialization, and local
database execution, while Qenlo measures a Rust in-memory `search_batch` call.
Chroma and USearch are approximate indexes; the exact Qenlo GPU paths are not
ANN implementations.

Raw configurations, samples, truth, and measurements are retained under
[`benchmarks/2026-08-28/real/`](../benchmarks/2026-08-28/real/). The comparison
files contain the workload compatibility checks and seeded 10,000-draw
whole-run intervals.

## one-percent selective rows

The same 100,000-row corpus with 1,000 eligible rows shows why selectivity is a
separate workload. Qenlo exact CPU is 0.2304 ms P95; GPU rows is 0.6766 ms and
GPU predicate is 2.8832 ms. All three returned recall 1.0 with zero filter
violations. The CPU-over-GPU-predicate ratio is 0.0799× (the GPU path is slower
for this selective cell), so the all-row GPU speedup must not be generalized to
selective queries.

## what remains untested

The preregistered investment gate is **1,000,000 × 768, 1% eligible, batch 1,
k=10, at least 2× lower P95 than the best validated CPU path**. It remains
untested. This host recorded about 4.54 GiB free RAM while two 1m×768 vector
copies alone require 6.144 GB, before metadata, the oracle, and GPU preparation
buffers. The run was not forced into an OOM condition. The 768-dimensional
source download is retained for a future machine with enough memory.

Linux, Metal, mobile, browser, service/HTTP competitors, and a controlled
multi-machine performance study are also outside this result record. Five runs
on a shared laptop provide a coarse interval, not a universal ranking.

## reproduce

Use fresh output directories and the prepared dataset described in the protocol.
For an actual GPU run, set `WGPU_BACKEND=dx12` and use a build with
`--features gpu-wgpu`; required GPU mode fails instead of silently falling back.
The Chroma procedure and its failed runtime ef sweep are documented in
[`scripts/chroma-replay.md`](../scripts/chroma-replay.md).
