# Compatibility policy

Qenlo is pre-1.0. Application APIs may change between alpha releases, but a
release does not silently reinterpret durable data or native calls.

## Portable and durable data

- Portable `.qn` format v1 remains readable for the rest of the 0.x series.
- Writers continue to emit v1 until a replacement has a documented migration
  path and compatibility fixtures in CI.
- Unknown snapshot or WAL versions fail closed with the found and supported
  versions. Qenlo does not attempt a lossy best-effort import.
- The test suite imports an immutable `.qn` fixture generated by the published
  alpha.4 Python wheel, then checks tombstones, generation, and search results.

## SDK and native ABI

Rust, Python, and TypeScript are the supported alpha SDKs. Go, Kotlin/JVM, and
Swift are previews: they are tested in the repository, but their packaging and
platform coverage are not release gates.

All non-Rust SDK packages in one release must use the native library built from
the same tag. Mixing native libraries and wrappers from different prereleases is
unsupported. Breaking C ABI changes require coordinated SDK version bumps and
conformance tests in the same release.

## Deprecation

Before 1.0, source-breaking API changes may occur without a full stable-release
deprecation cycle. When practical, Qenlo documents the replacement in the
changelog for at least one prerelease. Storage compatibility follows the
stronger policy above.
